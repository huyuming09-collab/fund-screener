## 0. 术语与双版本号

| 概念 | 定义 | 载体 |
|---|---|---|
| `MODEL_VERSION` | **产物/管线版本**：任何评分或筛选规则变动（权重/阈值/红线/筛选闸/打分机制/池归类）都必须递增 | `config.py`；所有产物顶层 `model_version` |
| `POOL_VERSIONS[池]` | **池规则版本**：该池最后一次被规则变动波及的 `MODEL_VERSION`，逐池独立 | `config.py`；`top20.json`/`data.js` 顶层 `pool_versions` + `pools[池].pool_version`；打分快照 payload 同带 |
| 递增的判断 | 改产品规则 → 递增；纯展示/性能/文档修复 → **不**递增（commit 标 `fix`/`docs`/`chore` 即可） | AGENTS §7（`config.py` 全参数改动属产品决策） |

三池**评分权重共用一个 `MODEL_VERSION`，但池版本可不同**——例如 v5.9 只改两债池，固收+ 池版本停留在 v5.8，
产物里两债池标 `v5.9`、固收+ 标 `v5.8`，各自可追溯。

## 2. 变更流程（强制，AGENTS §2/§3/§6 配套）

1. **拍板**：权重/阈值/红线/闸任何改动 = 产品决策，用户逐项确认（AGENTS §7）；
2. **证据留档**：回测/重放/IC 证据写入设计文档并交叉引用（如 docs/14 §6 重放、docs/12 全链路验证）；
3. **实施**：改 `config.py`（权重表/SCREENS/REDLINES/…）；
4. **四门验证**：`pytest` 基线 254 → `smoke_page.js` SMOKE PASS → 管线 `--skip-refresh` 重跑 →
   **位移对照**：改动池出位移报告、**未动池必须零位移**（改前快照 `data/.snapshots/<批次>/` 对比）；
5. **记账（同提交）**：`MODEL_VERSION` 递增 + 该池 `POOL_VERSIONS` 更新 + 本文件 §3 版本表加行
   （触及筛选规则的同步 §4 表）+ `STATUS.md §6` 条目；
6. **提交粒度**：一次提交只做一件事，中文 commit message，push 前确认暂存区不含 `运营/`。
