# 08 · 周更管线与卡片设计

> 2026-10-16 落地。对应需求：每周五收盘后更新数据并重新筛选 TOP20（超 20 只只取前 20）、
> 只对筛选后的基金打分（不全库打分）、以用户视角设计卡片（支付宝基金详情风）、
> 框架预留中长债/固收+/指数分类、代码结构便于后续改权重/筛选条件/打分标准。

## 一、周更管线（`fundscorer/pipeline.py`）

```bash
python -m fundscorer.pipeline                  # 完整周更
python -m fundscorer.pipeline --skip-refresh   # 不抓数据，用现有缓存重筛重评（调试）
python -m fundscorer.pipeline --top 20         # 覆盖输出条数（默认 config.TOP_N=20）
python -m fundscorer.pipeline --asof 2026-10-15  # 指定筛选基准日
```

### 定时（已装 crontab）

```
30 23 * * 5  flock -n /tmp/fundscorer_pipeline.lock -c 'cd /home/jetson/Desktop/基金选择指南 && .venv/bin/python -m fundscorer.pipeline >> data/pipeline_cron.log 2>&1'
```

- **每周五 23:00（Asia/Shanghai）**，`flock` 防重入；日志追加到 `data/pipeline_cron.log`，
  管线自身另写 `data/pipeline_YYYYMMDD.log`（漏斗/耗时/失败清单）。
- **错过的周期不补跑**（cron 语义）；错过一周就手动执行一次 `python -m fundscorer.pipeline` 补数。

### 六步流程

| 步 | 动作 | 要点 |
|---|---|---|
| 1 | `build_universe` → `crawl`（nav/f10/inst 并行抓取） | 基金列表缓存 3 天，周更自然过期 |
| 2 | `persist_nav` → `refresh_pool_metrics` | ① nav_full 固化（`data/nav_full/*.pkl`，筛选/回测的读取对象）；② **短债池指标强制重算**，绕过 `collect_all` 的陈旧缓存复用（旧实现 nav 变化不回传，是已修复的潜在缺陷）；写 `*.tmp` 后原子 replace，失败份额回退旧记录（stale_fallback） |
| 3 | `load_screen_inputs` → `screen_candidates` | 硬条件 S1~S5 + 性能条件 P1~P2，输出 9 档漏斗 |
| 4 | `score_pool(records, score_only=候选份额, quota_n=全池基数)` | **先筛后评**：只对候选逐只打分；分位序列/池中位数/逐年排名仍由**全池**构建 → 候选分数与全市场快照**逐位一致**（tests/test_screen_scoreonly.py 等价性验证）。全程不读不写 `full_scores.json` |
| 5 | `rank_candidates(top_n=TOP_N)` | v5.2 A 类份额 `score_capped` 降序，取前 20（内部 CSV 保留 star 列供复核） |
| 6 | 原子导出三件套 | `data/screen_report.csv`（20 行内部报表）+ `data/top20.json`（卡片数据契约，**无星级字段**）+ `web/data.js`（原型页数据）；三者全部就绪才 replace，异常时正式产物不动 |

### 保护线

- 候选 < 20 → 日志**显著告警**，阈值不自动放宽（已定方法论；放宽需人工评估 `SCREENS`）。
- 抓取/重算失败 → 记录清单，陈旧回退，**下周自动重试**（周更即滚动重试机制）。
- `n_ok == 0`（候选全部打分失败）或榜单为空 → 中止且不替换正式产物，返回码 1。
- 日志中出现 `[警告]` 不影响退出码，巡检 `grep 警告 data/pipeline_*.log` 即可。

## 三、周榜网页（`web/index.html`，响应式：手机满宽 / 电脑 480px 窄栏居中，file:// 双击可用）

> 2026-10-16 起展示层定位为**普通静态网页**（原计划微信小程序，因小程序对投研/荐基类内容有
> 合规限制而停做）。页面两处挂免责声明：列表页底部常显 + 详情页底部（决策 3）。

设计立场：**用户在选基场景下 3 秒内完成"值不值得点开"的判断**——先看四个硬数字，再看风险底线（无红线），
点开才是完整尽调。支付宝详情风：橙色头图、卡片分组、红涨绿跌。

### 榜单卡（列表页）

```
┌──────────────────────────────┐
│ [1] 创金合信尊盛纯债债券A          │  ← 排名徽标（前三金/橙/黄底色）+ 名称
│     002438 · 短债 · 评分 87.04   │  ← 代码·分类·评分（无星级）
│ ┌────┬────┬────┬────┐        │
│ │2.74%│3.56%│1.52%│2.27│ 4格核心指标 │
│ │近1年收益│近五年年化│近五年最大回撤│夏普│   │  ← 收益红/回撤绿（涨=红约定）
│ └────┴────┴────┴────┘        │
│ 规模 9.81亿 · 经理从业 11.4年 · 无红线 │  ← 底部一行风控速览
└──────────────────────────────┘
   （列表底部另有常显免责底栏 `.page-disc`，见下）
```

- 四格指标 = 用户点名的：**近一年收益、近五年年化、近五年最大回撤（全称）**、夏普比率。
- 底部 = 基金规模 + **经理从业年限**（按用户修订：不是任期）+ 红线状态（有红线项红色提示）。
- **卡片与详情页均不展示星级**（用户口径）；星级仍是内部筛选/复核字段（CSV `star` 列保留），随时可恢复。
- 分类 tab：短债（启用）/ 中长债 / 固收+ / 指数（禁用 +"敬请期待"占位）。
- **响应式**：`#phone` 手机满宽；≥640px 居中限宽 480px + 投影（窄栏居中单列，用户 2026-10-16 确认口径）；
  viewport 已放开缩放（无 `user-scalable=no`）。
- **列表页常显免责底栏**（`.page-disc`）：文案取 `D.disclaimer`（`cards.DISCLAIMER`），
  data.js 缺失时用同口径静态字符串兜底 —— 页面无数据时免责声明仍然在场。

## 四、实现决策记录（决策 1 / 2 / 3）

### 决策 1：先筛后评的分位基准

- **采纳**：`score_pool(records, score_only=候选份额, quota_n=全池基数)` —— 分位序列、
  池中位数、逐年排名仍从**短债全池 1161 份额**构建（本地列 rank，近似零成本），只对候选逐只执行
  打分/红线/评星。
- **拒绝**：候选集内相对分位 —— 会平移全部分数（幸存者内部重排百分位），
  破坏已验证的 v5.2 分数与星级配额口径。
- **验证**：`tests/test_screen_scoreonly.py::TestScoreOnlyEquivalence` 子集分数/红线/星级
  与全量打分逐位一致；真实数据核对（2026-10-16）：60 个候选份额与 `full_scores.json`
  逐位一致 60/60、星级不一致 0。
- **实现注记（顺序依赖已修复）**：`rank_stab` 赋值原与逐只打分交错（分位基准=列表前缀）。
  2026-10-16 随 `drawdown_repair` 基准修复一并改为**打分循环前统一赋值**（分位基准=全池），
  并重生成 `full_scores.json`；详见 §五审计记录 #3 / #5。

### 决策 2：指标刷新绕过陈旧缓存

- **采纳**：周更强制 `refresh_pool_metrics()`（全部 code 忽略 20h 时效直接 `collect_metrics`，
  失败回退旧记录，原子写）。
- **背景**：`collect_all` 缓存命中即复用、不判断数据变化 → nav 更新永不回传指标缓存
  （周更若不修，分数永远基于首日数据）。手动 rank 路径维持原行为不变。
- **连带修复**：nav_full 此前无写入代码（历史由一次性脚本维护）→ `batch.persist_nav()`
  在 crawl 后固化全部 code 的净值文件。

### 决策 3：展示层停做小程序、改静态网页（2026-10-16）

- **背景**：微信小程序对投研/荐基类内容有合规限制，原计划的小程序发布渠道不可行。
- **采纳**：展示层定位改为**普通静态网页**——`web/index.html` + `web/data.js`，
  file:// 双击或任意静态托管均可；无后端、无 API（FastAPI 服务层路线取消，见 README 路线图）。
- **适配**：手机端满宽（观感与原 375px 原型一致）；电脑端（≥640px）内容列居中、限宽 480px、
  加投影（窄栏居中单列，用户确认口径）；viewport 放开缩放。
- **免责声明**：公开页面须挂 → 列表页底部常显 `.page-disc`（文案 `cards.DISCLAIMER`，
  data.js 缺失时静态兜底）+ 详情页底部原区块；`DISCLAIMER` 文案同步升级为公开网页口径
  （自动生成的研究结论、不构成投资建议/推介、数据源可能延迟出错、历史业绩不代表未来、风险自担）。
- **不变**：后端评分/筛选/管线/数据契约字段全部不变，仅 disclaimer 文本变化。
